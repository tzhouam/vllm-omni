# Native Windows Omni edge Agent — rolling status (2026-10-06)

This Agent extends the accepted [single-device architecture](../../../analysis/architecture_local_engine_20260915.md) through Omni `StageRuntime`, its llama.cpp graph-stage client, `ResourceLedger`, and ordered stage events. The tested laptop is a Ryzen AI 9 HX 370 with 63.1 GiB installed RAM and an RTX 5090 **Laptop** GPU with 23.9 GiB installed VRAM. Windows build 26200, NVIDIA driver 610.71, AC power, binary and artifact hashes, batch size 1, and one active request are recorded in the [public aggregate](public_evidence/agent_native_smokes_20261005.json). Live free memory is lower than installed capacity and is checked before each new load.

The public aggregate is generated by [public_report.py](public_report.py) from 25 native profile indexes (20 smoke or setup attempts, four full corrected-memory protocols, and one full browser-text protocol), two load refusals, two navigation retests, one Qwen host-mapped text request, and two allowlisted Qwen loader logs. It publishes only reviewed fields, recomputed counts, hashes, and aggregate timing. Full prompts, answers, screenshots, page observations, tool payloads, model paths, and other verbose logs remain in the gitignored private `results/` directory on the profiling host. The SHA-256 values bind each public entry to those local records; a public hash is not itself a substitute for review of the raw evidence.

The separately reviewed [Qwen3-30B native observations](public_evidence/agent_qwen3_30b_native_20261006.json) bind its official whole GGUF to two private loader/request records without adding unprofiled attempts to the 25-index aggregate. Its successful result is one trivial text Agent request, not a route qualification. The newer [Gemma recorded-source memory profile](public_evidence/agent_native_memory_current_20261006.json) is published separately from that historical aggregate, with [bound diagnostics](public_evidence/agent_native_memory_diagnostics_20261006.json) and the updated [bilingual quality aggregate](public_evidence/agent_memory_quality_20261006.json). A separate [recorded-source browser-text profile](public_evidence/agent_native_browser_text_current_20261006.json) records the later complete fixed-page read protocol.

Early indexes recorded the installed `vllm_omni` distribution metadata even though native Windows loaded this checkout through `PYTHONPATH`; they did not record the actual imported source version. The historical aggregate labels the former as `vllm_omni_installed_distribution` and leaves `vllm_omni_loaded_source_version` unknown for those runs. Later profiles separate the two versions. The first full memory profile began before SHA-256 capture of the imported Omni source and loaded Agent/dependency runtime was added, so both digest fields are absent there. The next three full runs record imported Omni, vLLM, and stage-contract source identity and pass their raw trace and measurement protocol audits. Their source/runtime digests matched at measurement time. Subsequent browser boundary changes altered the imported Omni source, so **all four earlier full memory runs are historical for current-code release matching**. The fifth fixed-memory and newer browser-text runs below share later imported-source and runtime identities at measurement. A subsequent catalog metadata change alters imported-source identity again; strict current-head release matching requires new profiles.

Evidence depth follows the architecture's D/B/C/P/E vocabulary: the machine inventory is D; verified llama.cpp device execution is B; audited, complete fixed-fixture Agent requests are narrow P observations for their tested task and model. A failed or unreconstructible trace is retained as a failure observation. The two Qwen load refusals have no P-level model request; the later host-mapped single text request is a very narrow P observation. None of these smokes is a qualified performance profile or an estimate promoted as measurement.

The browser write boundary refuses `browser_click` and `browser_fill` before
target inspection or approval. DOM form submission remains disabled because
`FormData`, handlers, and external protocols can have effects beyond guarded
HTTP navigation. The new `browser_post` path is separate: it requires explicit
UI approval of the complete body and exact same-origin canonical ASCII URL,
then rechecks the body hash, current page, and HMAC fingerprint of applicable
cookies before one request. Body size is limited to 64 KiB, URL length to
2,048 bytes, media type to four allowlisted values, and the raw response
excerpt to 4 KiB. Redirects and automatic retries are disabled; timeout or
transport failure leaves the server-side result unknown. The isolated HTTP
client may differ from Edge in proxy, CA, and CSRF behavior. Unit and local
transport tests do not establish a live browser-write Agent result. Read,
exact-URL GET navigation, and browser screenshots remain implemented; the
fixed local fixture does not establish general open-web safety.

Desktop `screen_capture` is now a one-shot sensitive read. The trusted-task
policy masks URL/path-shaped `screen_capture` tokens, but wording such as a
negation or question can still be misclassified, so **every** capture requires
UI approval. Native approval displays and binds the foreground HWND, process
ID, title, and physical bounds. The UI restores focus and rechecks that exact
window; the backend checks again before and after grabbing the screen pixels
inside those bounds. The contract reports `capture_scope` as
`visible_screen_pixels_within_foreground_window_bounds`; a backend unable to
identify and bind that target is refused before approval or pixels. Overlays
or background visible through transparency may
appear in the image. If the Agent window was foreground when proposed, the
approval may bind to the Agent itself; a robust target picker and full visual
qualification are still pending. No earlier visual smoke establishes this new
path as an end-to-end qualified route.
