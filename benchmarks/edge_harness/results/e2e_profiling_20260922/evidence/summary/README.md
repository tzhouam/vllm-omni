# E2E check and profiling

All 60 pairings have a disposition. The timing tables below remain the 2026-09-22 measurements. The configuration matrix and affected per-cell reasons incorporate the [2026-09-23 scoped recovery runs](../../../e2e_recovery_20260923/README.md) and [WSL CPU/native Windows expansion](../../../e2e_expansion_20260923/README.md). The expansion adds separate 20-request serial MiniCPM-o text-to-speech profiles on WSL CPU and native Windows GPU, a Spark output-head component profile on the HX370 AMD NPU, complete Spark text-request profiles through standalone llama.cpp and a bounded Omni whole-session stage on native Windows CPU and Radeon 890M, native Windows CPU Qwen3-TTS text-to-WAV profiles through both standalone PyTorch and a bounded Omni whole-session stage, and a hybrid CPU+Radeon 890M Qwen3-TTS profile likewise repeated through a bounded Omni whole-session stage. A pinned GGUF MiniCPM-o route adds combined image+audio to text+speech runs on WSL CPU, native Windows CPU and native Windows Radeon 890M+CPU. All three now pass a bounded complete request through an Omni graph stage; the WSL CPU path additionally passed one warmup plus 20 serial measured requests. These are scoped synthetic cases, not full release qualification.

The WSL CPU and CPU+Radeon InternVLA cells also have [bounded Omni complete-policy profiles](../../../e2e_expansion_20260923/evidence/internvla_omni_policy/README.md): one warmup and 20 serial patterned synthetic requests per placement, plus admission refusal, cancellation and a public hybrid `AsyncOmni.generate` request. The [WSL RTX 5090 Laptop CUDA](../../../e2e_expansion_20260923/evidence/internvla_omni_cuda/README.md) and [native Windows RTX CUDA](../../../e2e_expansion_20260923/evidence/internvla_omni_windows_cuda/README.md) cells now have the same scoped Omni whole-policy pattern with 20 serial requests each, explicit host/VRAM admission, refusal, cancellation and public action requests. Separate native Windows [CPU](../../../e2e_expansion_20260923/evidence/internvla_omni_windows_cpu/README.md) and [CPU+Radeon](../../../e2e_expansion_20260923/evidence/internvla_omni_windows_hybrid/README.md) Omni profiles add 20 serial patterned requests per placement, refusal, cancellation and public action requests. These advance only the synthetic action-policy path. Real observations/reference actions, physical action units/order/step time, task quality, loading peak and sustained power/thermal behavior remain unverified. The earlier [Cosmos component and direct hybrid results](../../../e2e_expansion_20260923/evidence/internvla_cosmos_radeon890m/README.md) remain separate experiments. A new [20-request native Radeon MiniCPM-o profile](../../../e2e_expansion_20260923/evidence/minicpmo_omni_radeon_profile20/README.md) passed the scoped combined input/output path but exposed a large memory-sensitive latency regression versus its earlier one-request smoke; its row below supersedes the smoke for repeated-request timing.

A [follow-up MiniCPM-o storage experiment](../../../e2e_expansion_20260923/evidence/minicpmo_omni_native_weights_io/README.md) copied the same ten GGUF weights to native NTFS. One warmup plus 20 complete requests passed on Windows CPU (p50/p95 23.62/23.88 s) and Radeon+CPU (16.35/17.20 s), with no prefetch warnings. Separate one-request UNC controls were much slower; the original UNC 20-request Radeon profile remains valid for that path. Run order and OS cache were not controlled, so no causal or cross-placement speedup claim follows. A [real InternVLA Cosmos encoder NPU artifact attempt](../../../e2e_expansion_20260923/evidence/internvla_cosmos_amd_npu/README.md) passed fixed-shape CPU export parity but its tested A16W8 candidates failed the CPU numerical gate or VitisAI compilation; the AMD NPU cell remains NOT E2E.

The [WSL CPU Spark GGUF Omni profile](../../../e2e_expansion_20260923/evidence/spark_omni_wsl_cpu/README.md) adds a separate current-Omni complete-request path to the earlier vLLM INT8 CPU result. It passed two named prompts, 20/20 serial measured inventory requests at p50/p95 7.82/7.97 s, a public text request, context refusal and cancellation cleanup. The CPU-only llama.cpp build required explicit CPU-buffer placement evidence because it omits the Windows offload-count log line. This does not establish token streaming or broad quality.

A [native Windows Radeon+CPU Qwen3-TTS recovery probe](../../../e2e_expansion_20260924/evidence/qwen_tts_omni_windows_restart/README.md) now verifies that the owned server entered prefill before cancellation, then a fresh Omni stage with the same pinned weights and hybrid placement returned identical PCM under a new worker generation. The single recovery run supplements the earlier 20-request complete-WAV profile; it does not establish playable streaming, same-session continuation or sustained real-time speech.

A separate [native Windows RTX Spark GGUF Omni profile](../../../e2e_expansion_20260924/evidence/spark_omni_windows_rtx/README.md) passed two named complete text requests, 20/20 serial inventory requests at 0.294/0.302 s p50/p95, public `AsyncOmni.generate`, context refusal and a fresh-stage restart after confirmed server-started cancellation. Its pinned 1.7B Q4_K_M llama.cpp Vulkan0 route offloaded 29/29 layers to the RTX 5090 Laptop. This is distinct from the earlier 4B BF16 vLLM CUDA profile and does not establish token streaming or broad quality.

The [native Windows RTX Qwen3.8-27B NVFP4 attempt](../../../e2e_expansion_20260924/evidence/qwen38_omni_windows_rtx/README.md) loaded all three pinned weight shards but failed before inference during vLLM Marlin post-load scale permutation with an unsupported PTX toolchain error. The current Windows driver reports CUDA 13.3 while the installed vLLM wheel was built with CUDA 13.4. This narrows the Windows blocker to the tested runtime combination; it does not reverse the WSL scoped text/image pass or qualify a Windows output.

[A native Windows RTX Qwen3.8-27B FP8 recovery](../../../e2e_expansion_20260924/evidence/qwen38_omni_windows_rtx/README.md) completed scoped Omni text and synthetic image-to-text requests via an explicit Triton FP8 linear backend. One warmup plus 20/20 serial measured requests of each kind produced stable outputs at 3.070/3.214 s text and 4.184/4.380 s image p50/p95. The separate NVFP4 Marlin/PTX failure remains unresolved.

A [native Windows RTX Qwen3-TTS Omni hybrid route](../../../e2e_expansion_20260924/evidence/qwen_tts_windows_rtx/README.md) now returns complete 24 kHz WAVs with talker/codec on RTX Vulkan0 and predictor on CPU FP32. One warmup plus 20/20 serial outputs had identical PCM at p50/p95 complete-request wall 3.153/3.231 s for 2.72 s audio. Public audio, explicit host/GPU admission, refusal of an undersized GPU reservation and fresh-stage recovery after server-started cancellation passed. The PCM differs from the Radeon hybrid, and the complete-WAV RTF remains above 1; the existing CUDA sustained playback findings are separate.

A complete pinned [Spark 1.7B BF16 WSL CPU checkpoint and acceptance run](../../../e2e_expansion_20260924/evidence/spark_bf16_wsl_cpu/README.md) adds a second current-Omni text artifact to the GGUF route. Twelve prompts produced 128 tokens each with clean cancellation; all 12 token-ID sequences exactly matched standalone vLLM on the same checkpoint. One warmup plus 20 serial 28-prompt-token/64-output-token requests measured p50/p95 complete-request wall time 5.411/5.751 s and TTFT 0.129/0.146 s on the fork branch. A fresh-session restart after an eight-token cancellation reproduced the same 128 greedy token IDs, while the retired handle was explicitly rejected. This is WSL CPU full-text scope, not mobile generation or broad quality qualification.

On a hosted [Galaxy S24 Spark attention-layer experiment](../../../e2e_expansion_20260923/evidence/spark_s24_full_attention/README.md), a real one-layer W8A16 QDQ artifact executed on NPU and matched prior S25 component outputs exactly on one dataset. The 100-sample layer p50/p95 was 1.109/1.205 ms; the service's 1.098 ms estimated-time field was the sample minimum. FP32-source versus S24 output hidden-state relative L2 was 1.351% without a downstream token-quality gate. This adds component C evidence only; device-local generation remains absent.

The same W8A16 layer also ran on hosted [Snapdragon X Elite CRD](../../../e2e_expansion_20260923/evidence/spark_xelite_full_attention/README.md) and [SA8775P ADP](../../../e2e_expansion_20260923/evidence/spark_sa8775_full_attention/README.md) NPUs, with pinned-fixture outputs identical to S24/S25; the 100-sample component p50/p95 was 1.433/1.606 ms and 1.837/2.079 ms, respectively. On [RB3 Gen 2 / QCS6490](../../../e2e_expansion_20260923/evidence/spark_rb3_full_attention/README.md), that W8A16 graph failed QNN DLC loading even after target-specific recompilation. An FP32 ONNX CPU layer then passed with source-relative L2 below 9e-7, while a calibrated W8A8 NPU layer executed but had 20.9% hidden-state relative L2 and remains numerically unqualified. These hosted component outcomes do not establish full generation or comparable device speed.

A [Qwen3-TTS Code2Wav follow-up](../../../e2e_expansion_20260924/evidence/qwen_tts_vocoder_qualcomm/README.md) recovered source and target artifacts, a retained fixture, and raw historical profiles. On SA8775P, fresh GPU-requested inference saturated 96.63% of waveform samples and differed from original ONNX CPU by 11.832 relative L2; the same binary's CPU-requested output on the exact SA device matched ONNX CPU within 4.13e-6 relative L2. The CPU-requested route also has 100 component samples at p50/p95 5.384/5.534 s, with all 738 execution-detail rows on CPU; the GPU-requested path remains numerically failed. A separate SA FP16 QNN NPU vocoder artifact compiled but failed at inference without waveform output. Fresh RB3 GPU-requested inference was unsaturated but differed from CPU by 15.73% relative L2 (16.06 dB SNR), without a listening-quality gate; its 100-sample mixed CPU/GPU component p50/p95 was 3.099/3.133 s. The same binary requested on exact-RB3 CPU matched original ONNX CPU within 4.13e-6 relative L2 on the fixture; its 47-sample CPU component profile measured p50/p95 12.727/13.424 s with all 738 execution-detail rows on CPU. X Elite ONNX CPU vocoder inference passed on the same fixture with 8.09e-7 relative L2 versus local ONNX CPU; its 94-sample component p50/p95 was 6.384/6.644 s with all execution-detail rows on CPU. DirectML inference and profile both failed during provider initialization (Windows error 80070057); a separate FP16 QNN NPU vocoder inference returned an unsaturated waveform at 1.138% relative L2 / 38.88 dB SNR versus local ONNX CPU, but its NPU placement profile exceeded the service execution-time limit during graph preparation and returned no samples. None is a complete TTS stream.

The identical SA/RB3 TFLite binary matched original ONNX CPU within 3.45e-6 relative L2 in a separate local HX370 x86-64 LiteRT CPU control. Exact-device SA and RB3 CPU-requested outputs also matched within 4.13e-6 relative L2. This narrows the tested GPU-route numerical failures; RB3 CPU placement and specific faulty delegate operations remain unverified.

A separate [Qwen3-TTS talker decode-step attempt](../../../e2e_expansion_20260924/evidence/qwen_tts_talker_qualcomm/README.md) recovered a 28-layer ONNX export and synthetic fixed-cache fixture. Historical FP16 QNN context-binary inference executed on S24, S25, SA8775P and X Elite, but all four changed the CPU reference top-1 speech token with 8.57–9.43% logits relative L2; they are numerically unqualified on this fixture. An RB3 compile rejected floating-point input. Separate CPU-requested talker steps on X Elite ONNX, SA8775P TFLite and RB3 TFLite preserved CPU token 80 with logits relative L2 2.07e-5, 3.33e-5 and 2.29e-5; X Elite had 100 component samples at p50/p95 191.414/309.428 ms with all 1,744 execution-detail rows on CPU; SA had 100 at 52.635/76.925 ms with all 1,800 rows on CPU; RB3 had 100 at 138.022/139.642 ms with all 1,800 rows on CPU. No complete talker loop or TTS stream follows.

A [Galaxy S25 InternVLA Cosmos attempt](../../../e2e_expansion_20260924/evidence/internvla_cosmos_qualcomm/README.md) packaged the real Place_Markpen image encoder into one ONNX file after two CPU parity fixtures. FLOAT16 QNN DLC inference returned a latent within 0.0524% relative L2 of the source on one pattern; its 100-sample six-frame component profile had p50/p95 49.665/51.382 ms and all 121 execution-detail rows on NPU. Injecting that latent into the real policy on local CPU changed synthetic actions by 0.742% relative L2, without a task tolerance. The same encoder compiled to FP16 QNN DLC for X Elite CRD and SA8775P; same-fixture NPU-requested inferences returned finite latents at 0.0608% and 0.0613% relative L2 versus source, with both X Elite and SA8775P profiled on NPU. This advances component and action-sensitivity evidence, not device-local full-policy qualification. The Place_Markpen checkpoint names dataset a2d_real/a2d_pen_holder, which returned HTTP 404 under the current authenticated Hugging Face account. The official vLLM-Omni example names a different Place_Markpen archive in InternData-A1, but access to that gated dataset returned HTTP 403; [the access record](../../../e2e_expansion_20260924/evidence/internvla_real_observation_access/README.md) leaves real-observation reference-action validation open.

A [MiniCPM-o speech-head study](../../../e2e_expansion_20260924/evidence/minicpmo_tts_qualcomm/README.md) recovered the historical 20-layer source and matching S24/S25 fixtures. Both FP16 context-binary outputs preserved the ONNX CPU top-1 speech token on this one decode step with logits relative L2 of 0.346%/0.360%. S24/S25 100-sample component profiles attributed all 1,029 execution-detail rows to NPU, with p50/p95 8.537/9.006 ms and 7.197/7.615 ms. New FP16 QNN DLC compiles passed for SA8775P, X Elite and RB3. SA8775P same-fixture inference preserved CPU top-1 token 1867 with 0.3568% logits relative L2; its 100-sample component profile measured p50/p95 11.901/13.038 ms with all 944 execution-detail rows on NPU. X Elite same-fixture inference also preserved token 1867 with 0.3170% logits relative L2; its 100-sample component profile measured p50/p95 9.905/11.037 ms with all 944 execution-detail rows on NPU; RB3 FP16 QNN inference failed at graph load; its explicit TFLite CPU fallback returned 41 finite outputs, preserved CPU top-1 token 1867 and had logits relative L2 1.26e-6 versus ONNX CPU, with 100 CPU-requested component samples at p50/p95 59.518/71.347 ms and all 1,008 execution-detail rows on CPU. These are speech-head component results, not multimodal MiniCPM-o requests.

A [raw sustained-window audit](../../../e2e_expansion_20260924/evidence/qwen_tts_sustained_drift/README.md) found that the historical native Windows RTX Qwen3-TTS run slowed sharply after about 26 minutes: all 17 serial medium requests in minutes 27–30 underrun in simulated first-audio playout, with median RTF 1.331. A current-source instrumented 30-minute repeat did not reproduce the collapse: the final 119 requests had median RTF 0.185, with three brief simulated underruns. The cause of the original collapse and an underrun-free playback qualification remain open.

A further [Qwen3-TTS Qualcomm component audit](../../../e2e_expansion_20260924/evidence/qwen_tts_vocoder_qualcomm/README.md) measured an RB3 single-fixture INT8 QNN vocoder on NPU at 1.971/1.992 s p50/p95 across 100 samples, all 728 execution-detail rows on NPU, but its waveform differed from source CPU by 66.93% relative L2. Distinct explicit INT8 and W8A16 QDQ ONNX exports on local ORT CPU differed by 246.97% and 331.83% relative L2 on the same fixture, respectively; the INT8 graph required basic graph optimization because the default optimizer rejected duplicate node names. None of these results qualifies audio quality or a full stream. The [S25 CPU talker step](../../../e2e_expansion_20260924/evidence/qwen_tts_talker_qualcomm/README.md) preserved reference token 80 and profiled 100 samples at 30.161/31.301 ms p50/p95, all 1,800 rows on CPU; S24 CPU vocoder profiled 100 samples at 4.826/4.958 s, all 738 rows on CPU.

Additional [Galaxy S24 and RB3 InternVLA Cosmos encoder checks](../../../e2e_expansion_20260924/evidence/internvla_cosmos_qualcomm/README.md) returned finite same-fixture latents at 0.0613% and 2.20e-6 relative L2 versus source on S24 NPU and RB3 CPU-requested routes, respectively. The S24 placement profile measured 100 six-frame samples at p50/p95 64.314/67.472 ms with all 121 execution-detail rows on NPU. RB3 returned 46 six-frame CPU samples at p50/p95 13.018/13.053 s with all 590 execution-detail rows on CPU. Synthetic hosted-latent handoffs to the real policy on local CPU showed 0.631% and 0.594% action relative L2 for S24 and RB3; neither complete action policy ran on its device.
