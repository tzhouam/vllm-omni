# Qwen3-TTS native Windows hybrid stage after in-flight cancellation

The pinned Qwen3-TTS 0.6B CustomVoice route completed one more scoped recovery check on the native Windows HX370 machine. The first Omni `StageRuntime` served two named complete-WAV requests and one additional measured request. Its owned CrispASR server log then showed a fourth request entering `qwen3_tts[customvoice]: prefill` before the Omni stage cancelled it. Cancellation emitted no terminal audio, exited the worker and released the full 8 GiB host-RAM reservation without quarantine. A newly initialized `StageRuntime` used a different worker generation, retained the same four artifact hashes and Radeon Vulkan0 talker/codec plus CPU FP32 predictor placement, and returned the first sentence with the same 61,440-frame PCM SHA-256, `57f60228e2b456f6dfefc7e49df862c7bff6ba7cf39231ef1824f615948a1539`. No late output followed. The [independent audit](audit_report.json) checks the report, both raw server logs and the [saved WAV](tts_restart.wav).

This follows the [20-request hybrid profile](../../../e2e_expansion_20260923/evidence/qwen_tts_omni_hybrid/README.md), whose p50/p95 complete-request wall time remains **3.298/3.336 s** for 2.56 s of speech. The one measured request in this recovery run took 3.591 s and is not a new p50/p95 performance profile. The fresh request took 3.567 s after 4.607 s of fresh-stage startup. The run establishes fresh-stage restart after one genuinely started cancellation, not resumed same-session generation, playable chunk streaming, concurrency or sustained real-time operation. The previous RTF-above-1 and quality/thermal gaps remain.

The host was Windows 11 build 26200 on Ryzen AI 9 HX 370, Radeon 890M driver `32.0.22018.6001`, power scheme `Performance`; an RTX 5090 Laptop GPU was installed but not selected. [Hardware data](hardware.json) was captured immediately after the run. The local CPU/Vulkan CrispASR v0.8.35 build, Q8_0 talker, F16 codec and cached punctuation GGUF are pinned in both execution plans of the [raw report](tts_restart_report.json); their SHA-256 values and source revisions are documented in the [earlier hybrid record](../../../e2e_expansion_20260923/evidence/qwen_tts_omni_hybrid/README.md). All weights remain in local storage outside Git. The source-checkpoint/converter provenance and full same-checkpoint numerical parity are still unestablished.
