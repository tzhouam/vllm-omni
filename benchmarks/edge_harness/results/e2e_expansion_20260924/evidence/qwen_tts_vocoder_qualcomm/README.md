# Qwen3-TTS Code2Wav component across Qualcomm devices

**The retained Qwen3-TTS Code2Wav export does not yet have a numerically qualified SA8775P or RB3 GPU path.** A fresh inference on the exact hosted SA8775P ADP returned a severely saturated waveform on the same input for which original ONNX Runtime CPU and prior S25 GPU outputs remained unsaturated. RB3 produced an unsaturated but divergent GPU-requested waveform. Explicit CPU routes on both devices matched the original ONNX CPU waveform and passed node-placement profiling, but their measured vocoder latency remains a complete-stream concern.

A new [two-frame S25 export](s25/qnn_short_chunk/README.md) preserves 72 history frames and locally matches the eager decoder at 2.96e-6 relative L2 on one fixture. Its FP16 QNN DLC failed NPU-requested inference at Workbench's reported memory limit. A [TFLite GPU-requested version](s25/tflite_short_chunk/README.md) returned a finite waveform at 2.325% relative L2 versus local ONNX CPU; 100 component samples measured p50/p95 0.559/1.052 s for 0.16 s of audio, with 403 CPU and 335 GPU placement rows. This mixed route has median component RTF 3.49 and no listening-quality pass or complete stream.

The same historical 25-frame S25 TFLite target now has a [GPU-requested placement profile](s25/full_tflite_gpu_profile/README.md): 100 samples p50/p95 **0.839/1.157 s** for 2 s audio, with 403 CPU and 335 GPU rows and reported 374,591,488-byte peak. Its component median RTF **0.420** is below one, unlike the two-frame candidate. The retained waveform still differs from ONNX CPU by **4.24% relative L2** on one synthetic fixture, and the historical export has no exact checkpoint revision or listening-quality gate. This is a candidate for complete-stream evaluation, not supported mobile TTS.
The current pinned CustomVoice snapshot's eager 25-frame decoder separately
matched that historical ONNX CPU waveform at **1.89e-6 relative L2** on the
same fixture, strengthening numerical continuity without proving the
historical export revision.

On [Galaxy S24](s24/tflite_short_chunk/README.md), the same pinned two-frame TFLite source matched local ONNX CPU at 5.75e-6 relative L2 when requested on CPU, but its GPU-requested output saturated every sample and differed by 24.218 relative L2. The 100-sample CPU component p50/p95 was 3.433/3.873 s for only 0.16 s audio (median RTF 21.46), with all 738 rows on CPU. The mixed CPU/GPU component measured 0.601/0.895 s with 403 CPU and 335 GPU rows, but that timing describes numerically failed audio. A FP32-preserving delegate control remains pending; neither route is a complete S24 TTS stream.

The historical Workbench source model `mqyer339n` is a 423,655,047-byte ONNX graph with one FP32 input `[1,512,97]` and one 48,000-sample output. The [manifest](artifact_manifest.json) pins its SHA256, the retained Workbench fixture dataset `d7m80jl32`, a local ONNX Runtime 1.29 CPU output, compiled target downloads, and the prior [S25 GPU output](s25_reference_output.npz). The source export script identifies the Qwen3-TTS 0.6B CustomVoice model family, but did not attest the exact checkpoint revision; these results must not be promoted to a revision-qualified release claim. Large source/target artifacts and the fixture remain outside Git under `/home/zhout/project/edge_infer/models/`.

The [S25 historical inference](s25_reference_inference.json) on the same fixture differed from local FP32 ONNX CPU by **4.24% relative L2 / 27.46 dB SNR** ([comparison](s25_cpu_comparison.json)); that waveform has no listening-quality tolerance. A fresh [SA8775P inference](sa8775p/inference_report.json) used historical compiled TFLite model `mnze95don` and requested GPU. Its [output](sa8775p/device_output.npz) had **96.63%** of samples at absolute amplitude at least 0.999, RMS **0.989** versus CPU **0.0837**, relative L2 **11.832**, and SNR **−21.46 dB**. The fresh [profile](sa8775p/profile_report.json) attributed 403 execution-detail rows to CPU and 335 to GPU; 100 component samples had nearest-rank p50/p95 **1.776/1.880 s** (minimum 1.675 s). The [audit](sa8775p/audit_report.json) pins all output hashes, waveform differences and placement. This is measured execution of a **numerically failed** output, not a usable TTS performance result. The [SA8775P compile record](sa8775p/compile_report.json) pins the artifact and source IDs.

The S25 target's [historical producer job](s25/cpu_control/compile_report.json) was recovered from the exact compiled model used above. A new [CPU-requested inference](s25/cpu_control/inference_report.json) of that same target and fixture returned a finite unsaturated waveform at **4.04e-6 relative L2 / 107.86 dB SNR** versus original ONNX CPU. Its [placement profile](s25/cpu_control/profile_report.json) returned **100** component samples at nearest-rank p50/p95 **4.418/4.641 s**, with all **738 execution-detail rows on CPU** and reported inference peak memory **867,893,248 bytes**. The 2.585 s estimated-time field is the sample minimum. The [full audit](s25/cpu_control/audit_report.json) binds the numerical output, exact historical target and placement. This is a numerically matching component CPU route, not a playable complete stream. A separate [S25 FP16 QNN DLC compile](s25/qnn_fp16/compile_report.json) succeeded, but its [NPU-requested inference](s25/qnn_fp16/inference_report.json) failed with Workbench reporting that model memory usage exceeded device limits. No waveform or placement samples were returned; the [runtime log](s25/qnn_fp16/logs/jprl0k47p_runtime.log.gz) is retained. This is a failure of this fixed 97-frame FP16 artifact on the hosted S25, not a general S25 NPU impossibility.

A matching [S24 TFLite CPU fallback compile](s24/cpu_fallback/compile_report.json) succeeded from the same ONNX source. Its [same-fixture CPU-requested inference](s24/cpu_fallback/inference_report.json) returned a finite unsaturated waveform at **4.04e-6 relative L2 / 107.86 dB SNR** versus original ONNX CPU. The [placement profile](s24/cpu_fallback/profile_report.json) returned **100** component samples at nearest-rank p50/p95 **4.826/4.958 s**, with all **738 execution-detail rows on CPU** and reported inference peak memory **851,140,608 bytes**. The 3.583 s estimated-time field is the sample minimum. The [full audit](s24/cpu_fallback/audit_report.json) binds output and placement. This is a numerically matching component route, not a complete playable TTS stream.

The fresh [RB3 inference](rb3/inference_report.json) on the same fixture returned a finite, **unsaturated** waveform ([output](rb3/device_output.npz)). Its [comparison](rb3/inference_comparison.json) against original ONNX CPU was **15.73% relative L2 / 16.06 dB SNR**, still without a listening-quality threshold. The fresh [profile](rb3/profile_report.json) returned 100 component samples at nearest-rank p50/p95 **3.099/3.133 s** and 403 CPU plus 335 GPU execution-detail rows; the [audit](rb3/audit_report.json) ties the profile to this numerically unqualified output. Thus the bitwise identical SA and RB3 TFLite target downloads produce materially different outputs on their respective devices; target file identity does not establish runtime numerical parity.

A separate [local LiteRT 2.2.0 CPU control](local_litert_cpu/report.json) ran that **same pinned TFLite binary** on the WSL x86-64 HX370 host with four interpreter threads. Its [waveform](local_litert_cpu/device_output.npz) was finite and unsaturated, within **3.45e-6 relative L2 / 109.23 dB SNR** of the original ONNX Runtime CPU output. The [reproducer](../../../../experiments/probe_qwen_tts_vocoder_litert_cpu.py) checks binary/fixture/reference hashes and I/O contracts. This narrows the SA saturation to hosted runtime/device behavior rather than a universally bad TFLite conversion. The one local invoke is not a comparable performance profile and did not by itself establish embedded CPU placement or identify the specific delegate operation at fault.

On the **exact hosted SA8775P**, a [CPU-requested inference](sa8775p/cpu_control/inference_report.json) of that binary also returned a finite unsaturated waveform. The [same-fixture comparison](sa8775p/cpu_control/inference_comparison.json) was **4.13e-6 relative L2 / 107.67 dB SNR** against original ONNX CPU. Its [CPU-requested profile](sa8775p/cpu_control/profile_report.json) attributed all **738 execution-detail rows to CPU**; 100 component samples had nearest-rank p50/p95 **5.384/5.534 s** (minimum 5.250 s). The [full audit](sa8775p/cpu_control/audit_report.json) ties the numerical and placement results to the same binary and fixture. This is a working **component CPU route**, roughly three times slower than the numerically failed GPU-requested component profile; neither is a complete TTS request. The GPU-requested SA output differed from this SA CPU-requested output by **11.832 relative L2** and saturated 96.63% of samples. A fresh [FP32-preserving GPU-option inference](sa8775p/gpu_fp32/inference_report.json) also failed numerically: its [comparison](sa8775p/gpu_fp32/inference_comparison.json) had **11.389 relative L2 / −21.13 dB SNR** versus original ONNX CPU and **84.89%** saturated samples. Disabling the FP32-to-FP16 allowance does not rescue this tested GPU route. The exact faulty delegate operation still requires isolation.

The re-fetched *historical* [SA8775P profile](sa8775p/historical_profile_report.json) has 100 component samples, nearest-rank p50/p95 **1.751/1.874 s**, and 403 CPU plus 335 GPU execution-detail rows. The *historical* [RB3 profile](rb3/historical_profile_report.json) has 100 samples, p50/p95 **3.143/3.189 s**, also with 403 CPU plus 335 GPU rows. Their previously quoted 1.701/3.107 s estimated-time fields are sample minima, not medians. Both profiles exclude talker/predictor, stage handoff, streaming and full-request time.

An exact RB3 Gen 2 [CPU-requested control inference](rb3/cpu_control/inference_report.json) of the same TFLite binary and pinned waveform fixture returned a finite unsaturated waveform. Its [same-fixture comparison](rb3/cpu_control/inference_comparison.json) matched original ONNX CPU within **4.13e-6 relative L2 / 107.67 dB SNR**, with no saturated samples. The [placement profile](rb3/cpu_control/profile_report.json) returned **47** component samples at nearest-rank p50/p95 **12.727/13.424 s**, with all **738 execution-detail rows on CPU** and reported inference peak memory **778,768,384 bytes**. The service's 11.294 s estimated-time field is the sample minimum. The [full audit](rb3/cpu_control/audit_report.json) binds numerical output and placement to the exact binary and device. This is a numerically matching component CPU route, but its 12.727 s median for one fixed vocoder step is a substantial playable-streaming latency blocker; no complete stream was measured. The GPU-requested waveform remains numerically unqualified.

A new [RB3 INT8 QNN DLC compile](rb3/qnn_int8/compile_report.json) succeeded from the same ONNX source with the retained single fixture as calibration data. [Same-fixture NPU-requested inference](rb3/qnn_int8/inference_report.json) returned a finite, unsaturated waveform, but the [comparison](rb3/qnn_int8/inference_comparison.json) versus original ONNX CPU measured **66.93% relative L2 / 3.49 dB SNR**. It is numerically unqualified even on its calibration fixture. The [placement profile](rb3/qnn_int8/profile_report.json) measured 100 component samples at nearest-rank p50/p95 **1.971/1.992 s**, all **728 execution-detail rows on NPU**; the [audit](rb3/qnn_int8/audit_report.json) ties the profile to this numerically failed waveform. A separate explicit [INT8 QDQ quantization](rb3/qdq_int8/quantize_report.json) of the ONNX source, checked on local ORT CPU with [pinned reproducer](../../../../experiments/probe_qwen_tts_vocoder_qdq_cpu.py), differed from original ONNX CPU by **246.97% relative L2 / −7.85 dB SNR** on the same single calibration fixture ([report](rb3/qdq_int8/cpu_qdq_report.json)). Its default ORT optimizer rejected duplicate node names; basic optimization ran. A distinct [W8A16 QDQ quantization](rb3/qdq_w8a16/quantize_report.json) was also numerically poor on ORT CPU: **331.83% relative L2 / −10.42 dB SNR** ([report](rb3/qdq_w8a16/cpu_qdq_report.json)). These explicit QDQ exports and the compile-time INT8 DLC are distinct artifacts, so their differences do not isolate a QNN runtime operation. Neither quantized ONNX artifact passes the CPU numerical gate for an RB3 deployment compile; representative calibration and waveform listening tests remain necessary.

The X Elite [ONNX CPU inference](xelite/cpu/inference_report.json) succeeded on the pinned fixture. Its [waveform comparison](xelite/cpu/inference_comparison.json) to the original local ONNX Runtime CPU output was **8.09e-7 relative L2 / 121.84 dB SNR**, with no saturation. The fresh [CPU profile](xelite/cpu/profile_report.json) returned **94** component samples, nearest-rank p50/p95 **6.384/6.644 s**, with all **634** execution-detail rows on CPU; the service's 5.917 s estimated-time field is the sample minimum. The [full audit](xelite/cpu/audit_report.json) pins source, fixture, target, waveform, placement and percentiles. This is near-source component parity on one fixture, without a listening-quality or complete-stream gate. The first X Elite [GPU inference](xelite/gpu/inference_report.json) and [profile](xelite/gpu/profile_report.json) jobs failed because Workbench rejects specifying both compute unit and ONNX execution provider. The corrected [DirectML inference](xelite/directml/inference_report.json) and [profile](xelite/directml/profile_report.json) both failed during DML provider initialization with Windows error `80070057` (`The parameter is incorrect`), without an output or timing samples. A separate [FP16 QNN DLC compile](xelite/qnn_npu/compile_report.json) succeeded. Its [NPU-requested same-fixture inference](xelite/qnn_npu/inference_report.json) returned a finite, unsaturated waveform at **1.138% relative L2 / 38.88 dB SNR** versus original ONNX CPU ([comparison](xelite/qnn_npu/inference_comparison.json)). This is better waveform agreement on this fixture than the historical S25 GPU output, but lacks a listening-quality tolerance and verified NPU node placement. Its [placement profile](xelite/qnn_npu/profile_report.json) failed after exceeding Workbench maximum execution time while preparing the graph; no timing or per-node placement samples were returned. The [compressed runtime log](xelite/qnn_npu/logs/jpyoxmvr5_runtime.log.gz) retains the QNN HTP preparation/serialization trace. The [X Elite ONNX CPU compile](xelite/compile_report.json) passed after the older TFLite target was rejected on Windows ARM. These failures constrain the tested DirectML route, not all GPU or NPU artifacts.

A new SA8775P [FP16 QNN DLC compile](sa8775p/qnn_npu/compile_report.json) passed from the same source ONNX, producing target `mqvovl9lm`; [same-fixture NPU-requested inference](sa8775p/qnn_npu/inference_report.json) failed with Workbench message "Failed to fully run the model, failed after compiling." It returned no waveform or placement samples. This separate accelerator artifact therefore does not rescue the numerically failed TFLite GPU route; the measured CPU component route remains available. The failure applies to this FP16 QNN DLC artifact, not every potential NPU export. The [collector](../../../../experiments/collect_aihub_component.py) retrieves terminal inference/profile reports without resubmitting jobs, and the [audit script](../../../../experiments/audit_qwen_tts_vocoder_qualcomm.py) checks source/fixture hashes, device and model IDs, actual placement, waveform error, saturation and sample percentiles.

This is one fixed vocoder component with a retained input, not complete Qwen3-TTS. The next gates are a quality-passing SA/RB3/X Elite target, talker and code predictor numerical checks, device-resident handoff/co-residency, playable streaming, cancellation, memory admission and sustained power/thermal profiling.
