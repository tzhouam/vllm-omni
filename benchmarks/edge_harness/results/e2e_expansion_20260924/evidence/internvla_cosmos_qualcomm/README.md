# InternVLA Cosmos encoder on Galaxy S25 NPU: compile attempt

This tests the **real Place_Markpen Cosmos CI8x8 image encoder component**, not the action policy or complete InternVLA. The [source export](../../../e2e_expansion_20260923/evidence/internvla_cosmos_amd_npu/README.md) pins the checkpoint, FP32 `[6,3,256,256]` input, `[6,16,32,32]` output, two CPU parity fixtures and the original external-data ONNX files. The external data were embedded into one 125,112,088-byte ONNX file outside Git at `/home/zhout/project/edge_infer/models/InternVLA-cosmos-onnx/cosmos_encoder_embedded.onnx` (SHA256 `656a5263f584851a1457ef6dcf60b995f7c67b056b3c90a4f33c814f7caf9ec9`). The embedded form retained reference-relative ONNX CPU L2 errors of `8.74e-7` and `2.29e-6` on ramp and pattern fixtures.

Workbench source model `mn4okj3rq` was [submitted for Galaxy S25 QNN DLC compilation](s25/compile_submission.json) as job `jpxl4d1jp`, with `default_graph_htp_precision=FLOAT16`. The [compile](s25/compile_report.json) succeeded and produced target model `mqkp12rxm`. A [same-fixture pattern inference](s25/inference_submission.json) requesting NPU was submitted as `jp8ex43zp` and remained pending at this evidence snapshot. Compile success does not establish NPU execution, output parity, action quality, latency, or full-policy support.

The [generic collector](../../../../experiments/collect_aihub_component.py) can retrieve the pending output, and the [Cosmos auditor](../../../../experiments/audit_internvla_cosmos_qualcomm.py) checks source/fixture hashes, target/device/dataset identity, latent shape and finite numerical difference against the pinned source reference. Neither script converts an encoder-only result to policy support.

Next: retrieve and audit the device latent, inspect actual NPU placement with a profile if numerical error is acceptable, then test action-policy impact and a device-local stateful policy. Full multimodal observation processing, admission, cancellation and sustained profiling remain open.
