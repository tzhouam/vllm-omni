# Qwen3.8-27B GGUF on native Windows CPU

The pinned [ggml-org/Qwen3.8-27B-GGUF](https://huggingface.co/ggml-org/Qwen3.8-27B-GGUF) revision `efbb3b1f70a21d97fd4495240648405f7228554f` passed bounded complete text and image-to-text requests through the current Omni `StageRuntime` and a whole-session llama.cpp stage on Ryzen AI 9 HX 370 CPU. The Q4_K_M language file is 18,973,870,528 bytes (SHA256 `c600de0300ae8a0eb3a6c0b8b5561b8b96f16bd2c863c2a66c42de29d391a747`); the Q8_0 vision projector is 629,247,008 bytes (SHA256 `2e968a6af97ce35d8971890b257b9b7edabf20ad91450501fa53162a19ee33eb`). Both were copied to native NTFS, and the stage hashed the actual files before launch. The server was llama.cpp b11124, commit `1a679828f`, SHA256 `9ffc5919acb4cb43c7be5f3053b59014cce70a87d3a801fcad49c4f459984f52`; Omni ran through the native Windows vLLM 0.29 Python environment. [Hardware and driver record](hardware_runtime.json).

The [profile](profile20.json) used a 2048-token context, 128-token maximum output, one server slot, deterministic temperature zero, a 96×96 solid-red PNG, and short prompts requesting `ready` and `Red`. The stage reserved **28 GiB of host RAM**, verified `0/65` model layers offloaded, `CPU_Mapped`/`CPU_REPACK` model buffers, and `CLIP using CPU backend`. A [post-change smoke](placement_verify.json) also passed with explicit projector-backend enforcement. Loaded process RSS was 28,981,010,432 bytes at the admission check; this is a loaded-state sample, not a loading or request peak. The reservation was fully released at shutdown. The first [23 GiB attempt](attempt1.json) correctly refused startup when loaded RSS exceeded its reservation; its failed driver/server logs are retained.

After one warmup per type, **20/20 text** outputs were `ready` and **20/20 image** outputs were `Red`. Nearest-rank complete-request p50/p95 wall time was **1.656/1.697 s text** and **2.925/2.976 s image** at concurrency one. Startup was 23.19 s and is excluded. The [single-request smoke](attempt2.json), [server log](profile20.server.log) and [joint auditor](../qwen38_gguf_audit_report.json) preserve the inputs, every measured wall time, output, request epoch, artifact identity, placement and ledger state. The image path includes the real vision projector and autoregressive answer, so this is scoped P-level evidence for these inputs.

An existing [Spark GGUF text-route regression smoke](spark_text_regression.json) passed `Paris` and the inventory answer `1511` after the shared llama.cpp backend change, with 0/29 layers offloaded. This checks that adding the multimodal projector contract did not break the prior text-only stage.

Reproduce with [the Omni probe](../../../../experiments/probe_omni_llamacpp_qwen38.py), the pinned files and hashes above, `--device cpu --reserve-gib 28 --repeats 20`, and fresh `--server-log`/`--output-report` paths. Set `PYTHONPATH` to this checkout and use the native vLLM 0.29 environment. Run [the auditor](../../../../experiments/audit_qwen38_gguf_windows.py) against the parent `evidence` directory. The report records one startup and two-token answers; it does not qualify long contexts, 128-token generations, broader image/video quality, public AsyncOmni, cancellation/restart, concurrency scaling, loading/request memory peaks, or sustained power and thermal behavior.
