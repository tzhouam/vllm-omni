# Qwen3.8-27B GGUF on native Windows Radeon 890M

The same pinned Q4_K_M language model and Q8_0 vision projector as the [CPU run](../qwen38_gguf_windows_cpu/README.md) passed bounded complete text and image-to-text requests through one Omni `StageRuntime` stage and llama.cpp b11124 on the Ryzen AI 9 HX 370 laptop. The native Windows server selected **Vulkan1: AMD Radeon(TM) 890M Graphics**. Its [server log](profile20.server.log) reported **65/65 model layers offloaded to GPU**, a Vulkan1 model buffer, and `CLIP using Vulkan1 backend`; a separate Vulkan host buffer and shared system RAM were also present. This is a model and vision-projector Radeon route, not a CPU-only result mislabeled as iGPU execution.

The [profile](profile20.json) kept the CPU run's 2048-token context, 128-token maximum output, one slot, deterministic temperature zero, 96×96 red PNG and exact short prompts. The stage reserved **28 GiB of shared host RAM** and verified the pinned model, projector, server binary, layer assignment and named Vulkan adapter. A [post-change smoke](placement_verify.json) also passed with explicit projector-backend enforcement. Loaded process RSS was 20,523,040,768 bytes at the admission check; it is not a loading or request peak. The reservation was released at shutdown. The first [attempt](attempt1.json) records a mistyped command-line model digest rejected before launch; [the corrected smoke](attempt2.json) passed both requests.

After one warmup per type, **20/20 text** outputs were `ready` and **20/20 image** outputs were `Red`. Nearest-rank complete-request p50/p95 wall time was **3.101/3.181 s text** and **5.160/5.220 s image**, concurrency one; startup was 26.59 s and is excluded. Under these short prompts, this Radeon route was slower than the separate CPU profile, so the data do not support choosing iGPU for speed on this workload. The [joint auditor](../qwen38_gguf_audit_report.json) checks each raw output, placement line, percentile and ledger release.

Reproduce with [the Omni probe](../../../../experiments/probe_omni_llamacpp_qwen38.py) and the pinned files/hashes from the CPU record, `--device Vulkan1 --expected-device-name 'AMD Radeon(TM) 890M Graphics' --reserve-gib 28 --repeats 20`, plus fresh log/report paths. The placement evidence applies to llama.cpp b11124 and this driver; Windows/Vulkan enumeration can change. This is scoped P-level evidence for text and one synthetic image. Long contexts, long generation, broad visual quality, public AsyncOmni, cancellation/restart, concurrency, sampled memory peaks and sustained power/thermal behavior remain open.
