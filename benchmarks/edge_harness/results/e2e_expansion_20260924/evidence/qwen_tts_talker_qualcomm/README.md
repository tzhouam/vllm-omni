# Qwen3-TTS talker decode-step Qualcomm qualification attempt

This is **one fixed-cache-bucket talker decode step**, not complete Qwen3-TTS generation. The retained 28-layer ONNX source model `mq3xre4rq` has SHA256 `41feb08517678e94d9301e992d0df610fc60e7c9faba5600703298c86554fd22`, FP32 hidden input `[1,1,1024]`, rotary and mask inputs, 28 K/V cache pairs at length 256, and outputs `[1,3072]` logits plus 56 cache tensors. Its historical export identifies the Qwen3-TTS 0.6B CustomVoice family but does not attest an exact checkpoint revision. The 1.78 GB source and test arrays remain outside Git under `/home/zhout/project/edge_infer/models/`.

The deterministic synthetic input dataset `d7dw6pgy2` has SHA256 `0bf538e1b64dfc9737dc4f925d61c6e4ffa5075a5dcd7afb1e85ac3bd2d9afea`. A local ONNX Runtime 1.29 CPU reference output has SHA256 `ee0ead70e33c02c7d3d6bcb757c5cf0fcbb9eb6fc75c34abfbe8a4479657d5be`. The fixture exercises the stated tensor shapes, but does not represent a real text-to-speech request or establish token/audio quality.

Historical FP16 QNN context-binary [S24](s24/compile_report.json), [S25](s25/compile_report.json), [SA8775P](sa8775p/compile_report.json), and [Snapdragon X Elite](xelite/compile_report.json) compile jobs succeeded. Same-fixture NPU-requested inference succeeded on all four, but **all changed the CPU reference top-1 logit** on this synthetic step: CPU token 80 versus S24/SA/X Elite 1720 and S25 412. The [S24](s24/audit_report.json), [S25](s25/audit_report.json), [SA8775P](sa8775p/audit_report.json) and [X Elite](xelite/audit_report.json) audits report logits relative L2 **9.33%/8.99%/9.43%/8.57%**, respectively, with maximum K/V relative L2 **11.23%/11.71%/11.54%/11.50%**. These FP16 artifacts are numerically unqualified for this fixture; a successful graph execution is not speech-token parity. The [RB3 compile](rb3/compile_report.json) rejected floating-point input on this device. These are artifact-specific outcomes, not full-model support claims.

Its 57-output contract was exercised against the pinned CPU reference as a local self-check; that self-check is not device evidence. Requested NPU placement still needs a profile.
