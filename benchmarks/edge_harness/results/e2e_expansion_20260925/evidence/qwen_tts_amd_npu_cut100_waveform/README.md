# Qwen3-TTS two-frame vocoder: AMD NPU prefix to CPU waveform

**Disposition (2026-09-25): three real-weight NPU-prefix plus CPU-suffix two-frame waveforms pass the provisional 1% numerical gate; complete Qwen3-TTS remains NOT E2E on the NPU.** This is a stricter downstream check of the earlier [cut-100 NPU component](../../../e2e_expansion_20260924/evidence/qwen_tts_amd_npu_vocoder/README.md), not a text-to-audio NPU run. The exact CustomVoice revision is `85e237c12c027371202489a0ec509ded67b5e4b5`; the two-frame Code2Wav source SHA-256 is `e563541bf77200ac4c4ca9d6e01cd7e25c09f9274233a8d82eeccc57580830d2`. Each input is `[1,512,74]` and the 24 kHz output is `[1,3840]`, or 0.16 s of audio. The set is one retained export fixture and two windows from one CPU-generated code stream, not a representative multi-prompt listening set.

On HX370 native Windows 11 build 26200, ORT 1.30.0 and VitisAI EP 1.8.63.0, the [fresh prefix probe](cut100_live_probe.json) placed **one `vitisai` node**, recreated the earlier cut-100 output error of **0.3906% relative L2** against ORT CPU, and retained [CPU/NPU boundary tensors](cut100_paired_outputs.npz) plus its [raw ORT profile](cut100_profile_2026-09-25_01-19-36_129.json). Session creation took **340.787 s** and one cold prefix inference **6.660 ms**. These are component observations; neither is steady whole-vocoder latency. The EP compiler printed node-map and option warnings while completing inference; they are not treated as numerical or placement failures.

The [suffix replay](waveform_handoff.json), reproduced by [`probe_qwen_tts_npu_prefix_waveform.py`](../../../../experiments/probe_qwen_tts_npu_prefix_waveform.py), extracts the unchanged source graph after `val_340`, verifies its CPU input/output contract, and runs both measured boundary tensors through that same CPU suffix. The CPU boundary plus CPU suffix reproduced the full ORT CPU waveform **bitwise**. The NPU boundary plus CPU suffix produced a finite waveform at **0.0589% relative L2**, **64.60 dB SNR**, and **0.000224** maximum absolute difference from the CPU-boundary control. [All four replay waveforms](waveforms.npz), including the zero-boundary control, are retained. The isolated CPU suffix took 1.462/1.416 s for the two one-call controls. In the same Windows process, after one correctness call per route, 20 alternating-order repeats measured nearest-rank p50/p95 **1.528/1.569 s** for the unchanged full ORT CPU vocoder, **1.515/1.584 s** for CPU boundary plus CPU suffix, and **1.525/1.593 s** for the captured NPU boundary through that CPU suffix. Every repeated waveform matched its route's first output exactly. These are CPU replay measurements, not 20 live NPU calls. The suffix alone has p50 real-time factor about **9.47** for the 0.16 s segment; the observed 13 ms median full-versus-suffix difference is not a measured NPU speedup after transfer, compile, memory or power costs. There is no playable-stream claim.

The [generated-code preparation](real_code/preparation.json), reproduced by [`prepare_qwen_tts_real_code_short.py`](../../../../experiments/prepare_qwen_tts_real_code_short.py), truncates a captured code stream from one complete CPU Qwen3-TTS request at the same revision. Its first two-frame CPU waveform matches the matching part of the 25-frame CPU decode within **4.94e-7 relative L2**. A [fresh NPU run](real_code/npu_probe.json) placed one VitisAI node; the [unchanged suffix handoff](real_code/waveform_handoff.json) differed from the corresponding CPU waveform by **0.00414% relative L2 / 87.65 dB SNR**. A second window starting at generated-code frame 23 also had [one NPU node](real_code_tail/npu_probe.json) and [NPU-to-short-CPU waveform error](real_code_tail/waveform_handoff.json) of **0.01225% relative L2**. CPU prefix plus suffix reconstructed each full short-graph CPU waveform bitwise. The windows' raw [boundary](real_code/paired_outputs.npz) and [waveform](real_code/waveforms.npz) tensors, plus their [tail boundary](real_code_tail/paired_outputs.npz) and [tail waveforms](real_code_tail/waveforms.npz), are retained.

The cut-100 boundary contains float32-max attention-mask values (`3.402823e38`), which dominate its global L2 norm. Its repeated **0.3906% boundary L2** across distinct inputs is therefore a weak quality metric. The waveform gate is meaningful here: zeroing the measured boundary changes the CPU waveform by **4.86%**, **3.60%**, and **2.24% relative L2** across the three windows, respectively. Still, the later window's [CPU-only preparation](real_code_tail/preparation.json) differs by **3.51% relative L2** from the matching segment of the longer 25-frame CPU decode. The fixed 72-frame context omits earlier history, but this experiment does not isolate that as the sole cause. Preserving long-request chunk/state behavior is a blocker independent of NPU precision.

The previously tested *later* pre-decoder cut-486 NPU boundary still fails: it changes the CPU decoder waveform by 9.689% relative L2, and the rewritten full mixed graph changes it by 15.696%. This cut-100 result narrows that failure to work after the early prefix or its interaction with the decoder. It does **not** establish that arbitrary Qwen3-TTS segments pass, that speech sounds acceptable, or that a prefix split improves complete-request timing. Full text/talker/predictor/vocoder state, bounded streaming, cancellation, shared-RAM peak, quality and sustained power have not been exercised together on this NPU path. In the existing Omni CPU worker the official Qwen wrapper owns a variable-length vocoder, while this artifact accepts one fixed 72-context/two-new-frame segment; replacing that worker's vocoder with this graph requires an explicit state/chunk contract.

Next, capture segments from multiple generated prompts, resolve the later-window CPU history mismatch with an explicit state/chunk contract, and measure complete live NPU-plus-CPU segments in paired order against CPU. Only connect the NPU as an opt-in Omni stage if it preserves waveform/listening quality and improves complete TTS behavior after compile, transfer, memory and power costs.
