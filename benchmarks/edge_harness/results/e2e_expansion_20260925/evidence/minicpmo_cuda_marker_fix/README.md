# MiniCPM-o WSL CUDA: no accumulating stage-0 terminal markers

This follow-up uses the same pinned MiniCPM-o 4.5 checkpoint, red-square image and three-stage deploy config as the [preceding clean-shutdown profile](../minicpmo_cuda_shutdown_fix/README.md) on the HX370 laptop's RTX 5090 Laptop GPU under WSL2. The runtime reports vLLM 0.29.0 and Torch 2.13.0+cu130. The [report](report.json), [per-request JSONL](report.jsonl), [runtime log](run.log) and [two-second shared-memory samples](shm_samples.csv) retain the input/config hashes, environment, outputs, sampled memory, stage lifecycle and `/dev/shm` observations.

One warmup plus 20/20 serial measured image-to-text+speech requests returned identical correct red-square text and token IDs, and each returned 124,800 nonzero audio samples (5.2 s at 24 kHz). Nearest-rank complete-request wall p50/p95 was **15.679/15.964 s**, excluding 97.779 s startup. All three stage workers retired without a forced kill, `resource_tracker` warning or outer orchestrator timeout; the profiler exited 0.

The previous profile left approximately one unconsumed 116-byte stage-0 terminal-marker segment per completed request until engine shutdown. This graph has no stage-0 sender connector: its stage-0 output travels through the orchestrator, while the configured shared-memory edge is stage 1 → 2. The AR scheduler now checks the same explicit sender-role helper used by its model runner before enqueueing any connector chunk. A stage-0 worker with a real sender edge still sends terminal markers.

Across 188 samples taken about every two seconds, stage-0 shared-memory segments peaked at **three transient segments / 2,177 bytes**, returned to zero repeatedly during the run, and were zero after all 21 requests and shutdown. The stage-0 lockfile count was 53 at both the first and last sample. These observations remove the *observed* per-request accumulation for this serial image workload; short-lived transfers still occur. Sampling does not prove a hard memory bound under concurrency, long sessions or other pipelines. The previous and current timings are separate runs and do not establish a speedup. Speech alignment, broader image/audio quality, power and thermals remain open.
