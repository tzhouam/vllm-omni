# MiniCPM-o WSL CPU BF16 sender-role regression

This is one real-weight red-square image → text+speech request through the current three-stage Omni BF16/vLLM CPU path on HX370 WSL. It tests the stage-0 sender-role change after the [earlier clean CPU shutdown retest](../minicpmo_cpu_shutdown_final/README.md). The installed wheel reports vLLM 0.28.0 against Omni 0.29 source, with Torch 2.13.0+cpu, `VLLM_TARGET_DEVICE=cpu`, no visible CUDA device and eight OpenMP/MKL threads. The [report](report.json), [JSONL](report.jsonl), [runtime log](run.log) and [two-second shared-memory samples](shm_samples.csv) retain the input/config hashes, exact output and lifecycle evidence.

The single request described the red square and returned 124,800 nonzero audio samples (5.2 s at 24 kHz) in 55.082 s after 92.101 s startup. All three workers retired without force kill, resource-tracker warning or outer orchestrator timeout; the profiler exited 0. Across 83 samples, stage-0 shared-memory segments peaked at five transient objects and returned to zero after the request and shutdown, with no net stage-0 lockfile growth. Sampled WSL RAM used reached 32,866,381,824 bytes and swap used reached 6,766,510,080 bytes. This heavily swapped single request is a regression check, not a sustained memory or latency profile. Broader image/speech quality, concurrency and power/thermal behavior remain unqualified.
