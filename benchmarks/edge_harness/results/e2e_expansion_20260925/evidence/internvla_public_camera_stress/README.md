# InternVLA simulated-camera stress across HX370 placements

**Disposition (2026-09-25): complete Omni policy execution on five runs across four native-Windows placements; no Place_Markpen task E2E or qualified accelerator benefit.** This advances input robustness beyond the earlier patterned synthetic-camera profiles. It does not supply a matching real robot observation or reference action. The camera frames are from a *rendered simulation* of a different pen task, and the policy state is a synthetic checkpoint-mean vector. The resulting actions must not be interpreted as successful or safe robot commands.

The source is the pinned `griffinlabs/InternData-A1-LeRobot-v3.0-by-embodiment@c621c2e12e1f4aaa634f3d89e3573ca969087235` Genie-1 pen episode, task “Pick up the pen with the left arm and place it in the basket.” Frames 15 and 30 from head, left-hand and right-hand videos were resized with padding to 224×224 float32 RGB. The Place_Markpen checkpoint instead asks “Place the marker pen in its holder.” Its normalized 32-value state and 50×32 noise were set to zero; these are **not measured robot state**. The source video and checkpoint SHA-256 hashes, preprocessing, camera fields, task mismatch and final input hash `58c0dc3d68f6226e85766c3f831b3a2cd3e68d0550e9a86eca9036ed4e594277` are pinned in each profile's fixture manifest. The raw videos and generated fixture remain local; no source media or checkpoint weights are committed. The [source/schema audit](../internvla_public_observation_audit/README.md) explains why the public dataset cannot satisfy the target A2D task-quality gate.

The machine was Windows 11 build 26200 on an AMD Ryzen AI 9 HX 370, Radeon 890M and AMD NPU. The [prior environment capture](../internvla_joint_npu_radeon/environment.json) pins drivers and runtime versions: VitisAI ORT 1.30.0 EP 1.8.63.0, DirectML ORT 1.24.4, and a separate `torch-directml` worker for the full Radeon encoder. The same pinned Place_Markpen checkpoint, processor, Cosmos tokenizer, fixture, 16 GiB admitted shared-RAM demand, one warmup and five serial measured requests were used in each run. The actions are float32 `[1,50,32]`, with `control_ready=false` and unverified physical units, joint order and step duration. All runs passed finite/stable action checks; cancellation left no stale output or RAM reservation on accelerator routes. The [audited comparison](comparison.json) checks the fixture/model hashes, report percentiles, action tensors, placement reports and ledger release. The first and reverse-order joint runs differed by **1.102 s in p50** despite bitwise-identical outputs. Run order, OS caches, clocks, thermal state and power were not controlled; five requests are too few for a deployment performance claim. The prior 20-request [patterned synthetic joint profile](../internvla_joint_npu_radeon/README.md) also remains a separate fixture. No task tolerance exists for the observed 0.682–1.546% action differences from CPU. The architecture's whole-request benefit gate remains unmet; joint placement stays opt-in experimental.

Reproduction uses [the fixture preparer](../../../../experiments/prepare_internvla_camera_stress_fixture.py) with the three pinned local MP4s, immutable source revision, exact source task, checkpoint directory and `--frame-indices 15 30`; it writes `--output-fixture` NPZ and `--output-manifest` JSON. After verifying the input hash above, run [the Omni policy profiler](../../../../experiments/probe_omni_internvla_policy.py) on native Windows with `--input-fixture`, `--fixture-manifest`, `--capacity-gib 20 --reserve-gib 16 --warmups 1 --repeats 5 --abort-check`, each named `--placement`, and the exact model, graph, EP and interpreter artifacts recorded by the profile. Use `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`, the pinned Python interpreter, and distinct report/action/log paths. The first CPU invocation without those UTF-8 environment variables aborted during PyTorch import with a Windows GBK decode error, before model loading; its corrected rerun is the CPU profile above. Finally run [the audit script](../../../../experiments/audit_internvla_fixture_placements.py) over all five report/action pairs. The full joint invocation and runtime paths are in the [earlier joint experiment](../internvla_joint_npu_radeon/README.md); this experiment adds the same fixture flags to every placement.

Remaining gates: matching A2D Place_Markpen observations, reference actions and a declared task tolerance; verified action units/order/timing; controlled paired whole-request runs under measured power/thermal conditions; load peak, concurrency, post-cancel restart and deadline behavior. A camera-input stress pass alone cannot promote any cell to robot-task E2E.
