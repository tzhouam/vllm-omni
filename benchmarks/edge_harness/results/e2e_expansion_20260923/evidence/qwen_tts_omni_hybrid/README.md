# Qwen3-TTS 0.6B CustomVoice on native Windows CPU + Radeon 890M through Omni

This is a **scoped complete-request text-to-audio path** through the registered `qwen3_tts_crisp_hybrid` Omni pipeline and `external.crisp.tts.v1` stage. The stage owns one local CrispASR server process and uses Omni `StageRuntime`/`StagePool` for one-request admission, a declared 8 GiB shared-host-RAM reservation, request/epoch identity, terminal audio event, output acknowledgement and cancellation drain. CrispASR retains the talker, code predictor, codec and their internal state. The stage uses Omni's existing complete-request graph control path; it is not an ONNX graph and does not yet provide playable incremental audio or restart after an in-flight cancellation.

The host was Windows 11 build 26200 on Ryzen AI 9 HX 370, Radeon 890M driver `32.0.22018.6001`, with an RTX 5090 Laptop GPU also installed. The active Windows power scheme was observed as `Performance` after the run; temperature and package power were not sampled. The selected hybrid route exposed only the Radeon through `GGML_VK_VISIBLE_DEVICES=1`, used `CRISPASR_QWEN3_TTS_VULKAN_NATIVE=1` for the talker/codec, and pinned the five-layer code predictor to CPU FP32 with `CRISPASR_QWEN3_TTS_CP_BACKEND=cpu-f32`. The [server log](omni_crisp_tts_pinned_profile20_20260923.log) identifies the Radeon as Vulkan0, the CPU-pinned predictor and Vulkan0 codec loading. This is route/log evidence, not per-operator GPU profiling. The present backend is intentionally restricted to this verified HX370/890M shared-RAM route.

Both named PCM hashes match the [earlier standalone output](../qwen_tts_radeon890m_joint/README.md) exactly. The [raw profile JSON](omni_crisp_tts_pinned_profile20_20260923.json) retains all request times, frame counts, stage events, placement plan and ledger snapshots. The [first measured WAV](omni_crisp_tts_pinned_profile20_20260923.wav) was independently transcribed as the exact sentence by pinned Whisper tiny.en, WER 0 in the [ASR report](omni_crisp_tts_pinned_profile20_asr_20260923.json). ASR agreement is only an intelligibility proxy, not speaker or perceptual quality. The [public AsyncOmni JSON](omni_crisp_tts_pinned_public_20260923.json) records one terminal audio output of the same PCM hash using a real Qwen3-TTS HF config directory for pipeline resolution; the GGUF weights, rather than the HF weights, executed.

The profile cancelled a live request after the measured series, observed no stale audio, terminated its owned process and released the ledger with no quarantine. It does not prove the stage can continue serving after that active cancellation. A [4 GiB reservation was refused](omni_crisp_tts_pinned_reject_memory_20260923.json) before load, and a [different declared GPU was refused](omni_crisp_tts_pinned_reject_device_20260923.json); both left the ledger empty. The admitted 8 GiB includes 1.38 GB of pinned GGUF files plus a declared 5 GiB allowance for KV, activations, workspace, transfers, loading and headroom; loaded process RSS was 2,723,655,680 bytes. Neither number is a measured loading peak or complete iGPU-memory attribution. The route remained slower than real-time generation and was not checked for continuous playback, concurrent requests, longer speech, thermal throttling or 30-minute sustained behavior, so M2 release qualification remains open. The CPU+iGPU+NPU joint row is unchanged because no NPU participated.

Reproduce with the [stage profile script](../../../../experiments/probe_omni_crisp_tts.py) and [public API script](../../../../experiments/probe_omni_crisp_tts_entrypoint.py) on native Windows Python/vLLM 0.29 with `PYTHONPATH` pointing to this checkout, `PYTHONUTF8=1`, and `VLLM_ENABLE_V1_MULTIPROCESSING=0`. Supply local paths and the four hashes above, plus `--server-log`, `--output-report`, and for the stage profile `--output-wav --warmups 1 --repeats 20 --abort-check`. The public probe also accepts `--model-config-dir`. No mobile or embedded device is implied by this Windows run.

The later [2026-09-24 in-flight cancellation and fresh-stage restart probe](../../../e2e_expansion_20260924/evidence/qwen_tts_omni_windows_restart/README.md) closes the one-request restart gap for this exact hybrid route. The earlier 20-request timing and its other qualification limits remain unchanged.
